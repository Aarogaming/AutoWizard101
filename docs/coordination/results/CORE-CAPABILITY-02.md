# CORE-CAPABILITY-02

Typed standard fact vocabulary now records type, unit, producer, producer availability and freshness separately from actual readings. Card configuration rejects misspellings, incompatible operators and numeric filters. Missing or mistyped observed values remain unknown. Explicitly unavailable resources can be configured without inventing readings. Tests cover malformed conditions, unknown observations and location/destination separation. Root owns build/format/integration verification. No live access or new dependency.
Trusted routines may provide bounded additional fact definitions through JobRoutine.Facts. The service freezes those definitions at construction, rejects standard-name overrides and duplicates, and threads the same definitions through editor validation and runtime matching. A cross-game test checks successful custom-number evaluation and isolation from subsequent caller mutation. These extensions are code-owned; imported card JSON cannot register them.
Discovery follow-up: JobDeckService.FactDefinitions exposes read-only per-routine snapshots containing standard and frozen extension facts. The host publishes routineFacts and the UI can use the selected routine vocabulary. The custom-fact regression also verifies discoverability and snapshot type preservation.

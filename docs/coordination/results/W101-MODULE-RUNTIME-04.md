# W101 prepared module runtime

2026-11-11. Source implementation; coordinator owns native verification.

W101ModuleOperation prepares the existing sigil, menu-open or native-Idle entry
bundle under ModuleJobAdapter/ModuleOperation and the shared owner. One finite
loop reads UI-tree samples, transforms them through W101ModuleBindings, proposes
known module actions, and requires released receipts plus newer correlated
outcomes. Loading/unknown/dialogue cannot become blind input. No Idle exit,
walking, purchasing or generic arbitrary command is added.

The injected trusted transport must verify selected target and measured current
control geometry, call the readiness guard before input, and confirm releases.
No production transport factory is enabled here. The observation adapter must
independently establish OutcomeForProposalId; the loop never assigns success from
the fact that input was sent. Reader cleanup or input-release uncertainty latches
recovery. Cancellation, target/takeover, wall-clock and read-count budgets bound
work; trace and result evidence remain on disk.

Synthetic tests run through the actual scheduler with local test locks and no
OS input, checking sigil/menu/Idle, loading, dialogue, missing outcomes, takeover
and disabled admission. Tests do not qualify current W101 controls or geometry.
No builds, game access, desktop actions or dependencies run by this subagent.

ForCards supplies the concrete trusted card-adapter factory. It requires fresh
selected-target facts and mode qualification, creates a distinct visit, enforces
card timeout and native/menu method restrictions, and checks the configured sigil
prompt against independently observed sample text. A boolean prompt alone cannot
qualify a selected interaction. The default application host does not supply this
factory because production control geometry/semantic identity remain unqualified.

Additional synthetic regressions exercise actual deck→factory→owned module,
reader exceptions/recovery, unreleased input/recovery, mismatched selected prompt,
and timeout/freshness admission. The loop waits at least50ms between reads and
caps24reads; it is not an unrestricted polling worker. Coordinator verifies all
native builds/tests and records final counts separately.

# Selected W101 conversation — November 10, 2026

User intent: one selected quest step, clarified as the full conversation rather
than a single page. Closing dialogue is progression, never automatic cleanup.

## Current source

`ui-tree-watch --include-quest-context` optionally reads three exact game-owned
paths inherited from Deimos: the tracked objective, spoken dialogue text and the
advance control. Default observation does not read this text. Private branches
stay excluded. Text is bounded (256/2,048 characters); unknown, oversized,
ambiguous and unqualified layouts stay unknown. Loading/read failure clears
context; two consecutive matching readings produce `stableQuestContext`.

`W101QuestStep` prepares a one-action expected-objective transition using the
existing MenuModule. `W101QuestConversation` extends the same menu mechanism with
an optional progress scene and bounded repeated actions. It requires an exact
opening objective/dialogue selection. Each new page must differ from previously
advanced pages and follow an accepted, released receipt. The tracked objective
may change during the same conversation: turning in a talk objective can precede
the next quest offer. No fixed transcript or timed click sequence is used.

The selected conversation has at most 12 advances by default (configurable 1–16),
a 60-second total budget and a 15-second outcome deadline per action. It reports
completion only after dialogue closes and a nonempty different objective appears.
An optional exact expected objective can narrow that check. Otherwise the result
means **the tracked objective changed after this conversation**, not completion
of a whole quest or correctness of an inferred future quest chain.

## Input and ownership

The separately enabled `quest-conversation` CLI uses the existing scheduler,
selected process identity, source pins, control lease, stop file and recovery
guard. Every two-second observation restores its reviewed root hook and closes
its client handle before input. The input binding follows Deimos's Space dialogue
control, using addressed window messages with a bounded send timeout and an
attempted key-up even after an ambiguous failure. It never activates a window or
moves the desktop pointer. An accepted message is not a verified game outcome.

Desktop activity, held keys, target change, cancellation, unconfirmed release or
observation failure stops the run. It does not walk, battle, buy, feed, select a
new quest, or return to Idle. It may accept/advance the selected quest as part of
finishing its conversation; that requires the action opt-in. No generic key or
memory command is exposed. Scope is one conversation, not arbitrary dialogue
skipping across the game.

## Remaining gates

One opening turn-in and one follow-up offer are live evidence, not general
auto-quest qualification. The command still requires an explicit selected
objective/page. Add different NPC/branch examples, interruption recovery,
workspace configuration and a general between-run Idle policy before claiming
unattended quest operation. Navigation, battle, resource policies and quest
discovery remain separate qualified operations. A game-level timeout/reconnect
that happens between sparse observations cannot be assumed distinguishable from
all other scene changes; broaden independent state evidence before long runs.
